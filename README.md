# EbookText Studio v0.1 — Windowsで電子書籍の文章化

Windows上に**実際に表示されているページ**を、通常のページ送り操作で撮影し、ローカルのOCRで日本語テキスト、Markdown、画像PDF、検索可能PDFを生成するツールです。Kindle専用の内部APIを利用しないので、画面を通常表示できてキーボードでページ送りできるサービスに共通して使えます。

**Kindle（Windows版またはブラウザ版）、楽天Kobo、Google Play ブックス、DMMブックス、その他のビューア**を想定しています。ただし、すべてのビューアでの動作を保証するものではありません。画面撮影を保護するビューアでは黒い画面が保存される場合があります。このソフトはDRMを解除したり、ブロックを回避したりしません。

> 初めての方は、手順を順に説明した **[使い方ガイド](docs/使い方.md)** をご覧ください。

## ダウンロード後のセットアップ（Windows 10/11）

### 方法A: `setup.bat` で自動セットアップ（ソース版）

1. ZIPを「すべて展開」し、`setup.bat` をダブルクリックします。次を自動で行います（インターネット接続とwingetが必要。許可を求める画面が出る場合があります）。
   - Python 3.11〜3.13がなければ `winget` で Python 3.12 を導入
   - 専用の `.venv` を作成し、必要なライブラリをインストール
   - Tesseract OCRがなければ `winget` で導入
   - 言語データ（`eng` / `jpn` / `jpn_vert` / `osd`）を `%LOCALAPPDATA%\EbookTextStudio\tessdata` にダウンロード（管理者権限不要）。アプリは自動でこの場所を使います
   - **NDLOCR-Lite**（日本語書籍向けOCR、推奨）を取得し、専用の仮想環境に導入（不要なら `setup.bat -NoNdl`）
   - デスクトップとスタートメニューに「EbookText Studio」のショートカットを作成（不要なら `setup.bat -NoShortcut`）
2. ショートカット、または `run.bat` からGUIを起動します。

wingetが使えない環境では、Python 3.12（python.org）とTesseract（<https://github.com/UB-Mannheim/tesseract/wiki>）を手動で導入してください。

### 方法B: exe版（Python不要）

`build_exe.bat` を実行すると `dist\EbookTextStudio\EbookTextStudio.exe`（と配布用ZIP）が作成されます（ビルドには先に `setup.bat` が必要）。exe版を使う側は、フォルダ内の `install_ocr.bat` を一度実行してTesseractと言語データを導入し、`EbookTextStudio.exe` を起動します。exe版でNDLOCR-Liteの `src/ocr.py` を指定する場合はPythonが別途必要です（`ndlocr-lite` コマンドの指定を推奨）。

> **注意:** 自動セットアップ（`setup.bat` / `install_ocr.bat`）とexe版は、Windows実機でまだ検証していません。うまく動かない場合はエラー表示を添えて報告してください。

Tesseractの詳しい導入元: <https://github.com/UB-Mannheim/tesseract/wiki> 。日本語データが入らなかった場合は、`jpn.traineddata` / `eng.traineddata` を `%LOCALAPPDATA%\EbookTextStudio\tessdata`（または Tesseract の `tessdata`）に入れてください。言語が欠けている場合はGUIが不足言語を表示します。

## 画面キャプチャ → OCR

1. Kindleアプリ（またはブラウザ）で対象書籍を開き、**単ページ表示・適切な拡大率**にして、取り込みたい最初のページへ移動します。
2. GUIの「書籍名」「保存先」を指定します。書籍単位でフォルダを分けます。
3. 「画面で撮影範囲を選択」をクリックし、画面上の**本文領域だけ**をドラッグして囲みます。選択が終わったら画像の上下が切れていないか確認します。
4. 「最大ページ数」を短め（まず**3〜5ページ**）にして動作テスト。ページ送りのキー（右矢印、左矢印、PageDown等）をビューアに合わせます。
5. 「自動キャプチャ開始」をクリックし、カウントダウン中に**電子書籍のウィンドウを前面に出してクリックでアクティブ化**してください。アプリは最小化されます。撮影中はキーボードを操作しないでください。
6. 最初のページを撮影し、指定間隔でページ送り・撮影を繰り返します。**F8で停止**、同一画面が3回続いても終了します。ページ途中で終える場合も途中画像は保存されます。次回は続きを表示してから「キャプチャ開始」を押すと連番で追記します。
7. アプリに戻り「OCR / Markdown / PDFを生成」をクリック。完成物は書籍フォルダの `output` 内に保存されます。OCR結果を修正して再変換する場合は `replacements.json` を編集してOCRを再実行します（置換が反映されます）。

**キャプチャの制限（ページ送り方式）:** 1ページ表示推奨。本文が連続スクロール式のビューアでは1枚=1ページにならず、欠落や重複が発生することがあります。その場合は次の「連続スクロールモード」を使ってください。ページ送りキーは各ビューアで異なります。**マルチモニタではプライマリディスプレイ上**で範囲選択します。ウィンドウサイズや表示倍率は撮影途中で変えないでください。CPU速度やページの描画時間に応じ「待機秒数」を1.5〜3秒程度に調整してください。

### 連続スクロールモード（スクロール式ビューア向け）

出力画像の上下には24pxの白い余白を付けます（画像の端に接した行をOCRが読み落とすのを防ぐため）。

M3Bookのように、ページ単位ではなく**縦に連続してスクロールする**ビューアでは、「撮影方式」を「連続スクロール」にします。ページ送り方式のように1回の操作で1ページ進まないため、欠落や重複が起きることを避けるための方式です。

1. ビューアを本文の撮影を始めたい位置に表示し、「画面で撮影範囲を選択」で**本文が見える領域**を囲みます（ツールバーは含めない／含めても自動で除外されます。スクロールバーを含めた場合は「右端除外px」に幅を入れます）。
2. 「撮影方式」を「連続スクロール」、「操作」を選びます。通常は**マウスホイール**を推奨します（1回の移動量が小さく、重なりを細かく調整できます）。PageDownは1回で画面の約87%動くため重なりが少なく、大きな図表では不利です。
3. 「1回の量」は**自動**のままで構いません。最初の1回で実際に動いた量（px）を画像の照合で測り、以後は画面の高さに対する「重なり%」（既定25%）になるよう回数を自動調整します。
4. 「自動キャプチャ開始」→カウントダウン中に本文をクリックして操作できる状態にします。F8で停止、同じ画面が3回続けば本の末尾として終了します。

**仕組み:** 撮影ごとに前の画像との共通部分を画像照合し、実際に動いた距離を求めて新しい部分だけを縦に継ぎ足します（キー入力の回数は信用しません）。継ぎ足した長い画像は、**空白行のところで**ページ状の画像（`pages/page_00001.png`…）に切り分けるので、文章の行や図表を途中で切りにくく、OCR以降は従来の画像とまったく同じに扱えます。

- **読み込みが遅いページ:** 画面の変化が止まるまで待ち、新しい部分が真っ白のときは追加で待って撮り直します。次の撮影の重なり部分でも読み込み後の画像に置き換えます。
- **安全停止:** 前の画像と一致しない（照合誤差が大きい）場合は、待機・半分のスクロール量での撮り直しを試し、それでも一致しなければ**そこで停止**します（確認用画像は書籍フォルダの `scroll_debug`）。それまでの画像は正しい内容で保存されています。
- **途中再開:** F8停止時は文の途中の末尾を保留し（`scroll_state`）、次回、続きの位置で開始すると、前回の最後の画面と照合して**重複も欠落もなく**つなぎます。前回と全く違う位置から始めると警告のうえ新しい区間として保存します（その境目は目視確認してください）。
- **記録:** `scroll_log.json` に各回の移動量・誤差を、`manifest.json` に `capture_mode: continuous_scroll` を記録します（画像は記録しません）。
- **従来のページ送り方式には影響しません。**

> 注意: 連続スクロールではビューアのページ番号・柱（ランニングヘッド）が本文の途中に写ります。「柱・ページ番号・版権表記を本文から外す」は画像の上下端の行を対象とするため、この方式では効果が限定的です。必要に応じて `replacements.json` や出力の編集で整えてください。

## 既存の画像・PDFからOCR

画像が既にある場合は「画像フォルダを取り込む」。ファイル名のアルファベット順でページになります（例 `001.png`, `002.png`）。

PDFがある場合は「PDFを取り込む」。PDFは180dpiでページ画像に展開します。**PDF内に元々選択可能なテキストが40文字以上あるページは、その元テキストをMarkdown作成に優先利用**します。元PDFを完全に保存するわけではないため、必要であれば元ファイルは別途保管してください。

**章ごとにPDFが分かれている本**は「PDFフォルダを取り込む（章ごとのPDFを1冊に）」を使います。選んだフォルダの中のPDFを、サブフォルダも含めて、パスの自然順（`第2章` は `第10章` より前）で1冊につなげて取り込みます。`~$` で始まるファイルは除きます。つないだ範囲は `manifest.json` の `source_pdfs`（各PDFの最初と最後の画像番号）に残ります。1冊に取り込んだ後でPDFを足すことはできないので、足りないときは新しい書名で取り込み直してください。

### 取り込み時の整形（iPadのスクリーンショットPDFなど）

画像・PDFの取り込み時に、次の整形を自動で行います（GUIの「取り込み時の整形」で個別にオフにできます）。

- **上下のステータスバー除去**: 画面上部の時刻・電池残量、下部のホームバーなど、暗い帯を切り落とします。
- **見開きの自動分割**: 横長（幅/高さ ≥ 1.25）の画像を、ページ中央の余白（のど）で左右2ページに分けます。左→右の順です。縦書きの本は「右開き」にすると右→左の順になります。単ページの画像はそのままです。
- **PDFの元画像を元の解像度で取り出し**: ページ全体が1枚の画像のPDFは、再描画せず埋め込み画像をそのまま使います。

見開き全面にまたがる画像（章扉の帯など）では、分割位置が数十px中央からずれることがあります。

OCR後は、次の後処理が自動で働きます（GUIの「柱・ページ番号・版権表記を本文から外す」でオフにできます）。

- 状態表示の行（`21:58 5月28日 (木)` など）、`JCOPY` を含む版権表記、複数ページに繰り返し現れる柱（章名の見出し行）を本文から除外します。
- ページ番号らしい行は本文から外し、`全文.md` のページ見出しコメント（`<!-- source: …, page: 138 -->`）に残します。
- **低信頼の行の再読み（Tesseractのみ、標準でオン）**: ページ全体の読み取りで信頼度の低い行（既定: 信頼度80未満）を、その行だけ切り出して単独で読み直し、信頼度が明確に上がった場合だけ置き換えます。色つきの帯の見出し、表の中の語、小さい脚注などで効果があります。実測では再読みした行の約4割が改善します（GUIの「低信頼の行を再読み」、CLIの `--no-reread` でオフ）。再読みの結果は `全文.md`・`全文.txt` と `検索可能PDF.pdf` の文字層の両方に反映されます。再読みでOCR時間は約1.6倍になりますが、下記の並列処理で相殺されます。
- **並列OCRと検索可能PDF（Tesseract）**: 複数ページを同時にOCRします（既定: CPUコア数、最大8。CLIの `--workers N` で変更）。検索可能PDFの文字層は、本文OCRと同じ結果（行ごとの位置つき）から作るため、OCRは1ページにつき1回で済みます。4コアの環境で8ページ31秒でした（従来は137秒）。
- **`output/要確認.md`**: 数値・単位（mg、mmHg、%、日、歳など）・範囲を含む行の一覧を作ります。`60こ70%`（本当は60～70%）のような、数字の間の記号の誤読が疑われる行には「誤読の疑い」が付きます。医療数値は必ず原本と照合してください。
- **`output/OCR抜け確認.md`（OCR抜けの検出、標準でオン）**: OCRは行ごと、または行の途中を読み落とすことがあり、しかも実行のたびに結果が変わります。そこで画像の「文字がある位置」とOCRの「読み取り枠の位置」を突き合わせ、読まれていない疑いのある箇所を探します。①枠が無い行（行ごと未認識）、②行の途中だけ枠が無い（途中が未認識）、③枠はあるのに読めた文字数が枠の幅に比べて少ない（行の途中の文字が欠けた疑い）の3種類です。疑いのある画像は、該当箇所を赤枠で囲んだコピーを `output/audit/` に作るので、原本と見比べて確認してください（`replacements.json` では直せないので、必要なら画像を指定して再OCRするか手で補います）。図の中の小さな文字（図中ラベル）も「未認識」として挙がることがあり、また画像の上下端にあるページ境界のバーや脚注は対象から外しています。あくまで「ここを見てください」という目印で、結果が空でも抜けが無い保証にはなりません。位置情報の無いページ（PDFの既存テキスト層を使ったページ）は確認できません。GUIの「OCR抜けを確認」、`OCROptions(audit=False)` でオフにできます。
- **抜けの自動補修（標準でオン）**: 抜けの疑いがある箇所だけを小さく切り出し、拡大して**同じOCRエンジンで読み直し**、結果を `全文.md`・`全文.txt`・検索可能PDFに差し込みます（行まるごとの抜けは前後のOCR行の間に新しい行として、行の途中の抜けはその行の前後に追記、文字数不足は読み直しで文字数が増えた場合だけ置換）。差し込んだ内容と、補えなかった箇所（前後の行が見つからない、読み直しても読めない、既に隣の行にある、など）は `OCR抜け確認.md` に一覧が出ます。補修後にもう一度確認し、まだ疑いの残る箇所は赤枠画像に出ます。元のOCR結果（`ocr_cache`）は書き換えません。実データ（NDLOCR-Liteの4ページ）で、OCR行を1行ずつ消して補修できるか試したところ、検出できた105行のうち97行（約92%）が元の位置にそのまま戻り、残り8行も文字の欠落はなく、行の区切りか順序が変わる程度でした（読み直しが正しく読めた場合の話です。再読み自体の誤読は防げません）。検出できなかったのは23行（表や枠の中の、行間が詰まった行が中心）でした。GUIの「抜けを読み直して補う」、`OCROptions(repair=False)` でオフにできます。

### 構造化Markdown（表は表として、図は画像として。標準でオン）

`全文.md` は、ページの本文を連結しただけのものではなく、**見出し・段落・箇条書き・表・図**を読み順に並べたMarkdownになります（従来のページ順の連結は `全文_ページ順.md` に残ります）。GUIの「表・図・見出しを構造化したMarkdownにする」、CLIの `--no-structure` でオフにできます。

- **表**: 罫線を画像から検出してセルの格子を復元し、OCRの行をセルに入れます。罫線が途切れている所は結合セルとして扱い、Markdownでは結合セルの内容を各行に繰り返します（各行が単独で読めるように）。点数表のように、罫線の無い1つのセルに「<30%減少／30〜50%減少」と項目が縦に並び、隣の列に点数が並ぶ場合は、点数の行に合わせて行を分けます。ページ（連続スクロールのページ境界を含む）をまたぐ表は1つにつなぎ、行の途中で切れたセルは結合します。表ごとに原画像（`output/tables/*.png`）とCSVを保存し、表の下にリンクを付けます。
- **表の数値の読み直し（Tesseract、標準でオン）**: NDLOCR-Liteは表の中の短い数字を取り違えることがあります（実測で `8→00`、`12→11`、`-1→11`、`-2→21`、`20→10`、`24→14`、`or→15` など）。数字だけの短い行を切り出してTesseractで読み直し、信頼度が高くきれいな数値のときだけ置き換えます（小数点を消す置換はしません）。`2≦` が `25` に化けたような、記号の読み落としが疑われる場合は `2≦` として `要確認.md` に挙げます。置換・要確認はすべて `要確認.md` の末尾に一覧が出ます。GUIの「表の数値をTesseractで再確認」、CLIの `--no-numcheck` でオフ。
- **図**: 「図1」などのキャプション（色付きの番号札）、NDLOCR-Liteの図版判定、画像中の描画領域から図の範囲を求め、`output/figures/*.png` に切り出して `![図1 …](figures/…)` として埋め込みます。図の中の文字は本文に混ぜず、枠・色の付いた箱ごとにまとめて「図中の文字」として図の下に置きます（NDLOCR-Liteは図版の中の文字を読まないため、Tesseractがあればそこだけ読み足します）。
- **見出し・箇条書き・段落**: 文字の大きさ、中央寄せ、NDLOCR-Liteの「タイトル本文」判定から見出しを、◆・●・①や「ぶら下げインデント」から箇条書きを作ります。行の折り返しはつなぎ、ページ（スクロールのページ境界）をまたぐ文もつなぎます。柱・ノンブル・索引タブ（余白の縦書き）は本文から外し、ノンブルは `<!-- p.22 ここまで -->` として残します。
- **キャプション番号**: 色付きの番号札（表17・図6など）はNDLOCR-Liteが誤読しやすい（表7、■■など）ため、札の部分だけ白黒反転してTesseractで読み直します。
- **自動補正（`output/自動補正ログ.md`）**: OCRでほぼ確実に起きる誤りだけを直し、すべてログに残します。カタカナの間の「一」「-」→「ー」、カタカナ語の中の漢字の見間違い（力→カ、口→ロ など）、血液ガス表記の下付き数字（`cmH,O`→`cmH2O`、`FIO,`→`FIO2`、`PaCO,`→`PaCO2`）、数字の後の単位（`mL/kq`→`mL/kg`、`mmHq`→`mmHg`）、数字の前の `〈`→`<`、`Stagel`→`Stage1`、`Grade Il`→`Grade II` など。さらに**本自体を辞書として**、何度も出てくるカタカナ語と1文字だけ違う（ベ/ペ、バ/パ、濁点の有無など）まれな表記を多数派に揃えます（`ヘルベス`→`ヘルペス`）。書籍フォルダに `glossary.txt`（1行に1語）を置くと、その語を正しい表記として優先します。
- NDLOCR-Liteのレイアウト情報（表組・図版・柱・ノンブル・読み順）を `ocr_cache/*.ndl.xml` に保存して使います。このため**この版に更新して最初の変換では、NDLOCR-Liteのページが一度だけ再OCRされます**。

構造化は補助的な処理で、失敗した場合は従来どおりページ順の `全文.md` を出力します。表・図・数値は必ず原画像（`tables/`・`figures/`）と照合してください。

## OCRエンジン

日本語の書籍（特に医学書）には **NDLOCR-Lite を推奨**します。`setup.bat` が自動で導入し、導入済みならGUI・CLIの既定エンジンになります。

### 実測での比較（医学書3冊のうち、iPadスクリーンショットのPDF）

同じページを、手で書き起こした原文と比べた類似度です（1.0が完全一致）。Tesseractはこのコンテナのapt版の日本語データ（fast）と高精度版（best）、いずれも低信頼行の再読みあり。

| 対象 | Tesseract（fast） | Tesseract（best） | NDLOCR-Lite |
| --- | --- | --- | --- |
| 本文13行（数値を多く含む） | 0.945 | 0.955 | **0.987** |
| 本文中の数値の再現率 | 0.947 | 0.895 | **1.000** |
| 色つきの表3（疾患名の列挙） | 0.854 | 0.950 | **0.973** |
| 色つきの囲み（表4） | 0.927 | 0.879 | **0.933** |

NDLOCR-Liteは `50～60歳` の「～」、`98%`・`94%`、文献番号の上付き（`5,6)`）まで読めました。ただし完全ではなく、`摂食歴→損食歴`、`肺吸虫→胸吸虫`、`ヘルペス→ヘルベス` のような誤読が残ります。**医療数値・薬剤名は必ず原本と照合してください**（`要確認.md` を活用）。速度は1ページあたり数秒（CPU）で、Tesseractの並列処理と同程度です。

### 1. NDLOCR-Lite（推奨）

国立国会図書館の[NDLOCR-Lite](https://github.com/ndl-lab/ndlocr-lite)（CC BY 4.0。レイアウト認識モデルのバックボーンにはDINOv3を使用しており、そのライセンスにも従います）を使います。

- **自動導入**: `setup.bat` が公式リポジトリのZIP（約150MB）を `%LOCALAPPDATA%\EbookTextStudio\ndlocr-lite` に取得し、専用の仮想環境 `%LOCALAPPDATA%\EbookTextStudio\ndl-venv` に必要なライブラリを入れます。不要なら `setup.bat -NoNdl`。失敗してもTesseractは使えます（再実行でやり直せます）。
- GUIの「OCRエンジン」で選び、コマンド欄は `auto`（導入済みのものを使う）のままにします。自分で用意した場合は、`ndlocr-lite` コマンド、または公式ソース版の `src/ocr.py` のフルパスを指定できます。CLIは `--engine NDLOCR-Lite`（導入済みなら省略可）。
- 全ページを公式の `--sourcedir` で1回実行し、生成TXTとJSON座標からMarkdownと検索可能PDFを作ります。縦書きの位置合わせは十分検証されていません。
- exe版では、NDLOCR-Liteの導入にPythonが必要です（`install_ocr.bat` はPythonが見つかる場合のみ導入します）。
- 場所を変えたい場合は環境変数 `EBOOKTEXT_NDL_HOME`（リポジトリ）、`EBOOKTEXT_NDL_PYTHON`（Python）で指定できます。

### 2. Tesseract（軽量・追加導入不要）

`Tesseract` を選択し、言語は `jpn+eng`、PSM=3（レイアウト自動）を推奨します。単段組ならPSM=4/6、文章の配置が変則的なら11も試せます。画質補正・低信頼行の再読み・並列処理が使えます。OCR前処理はテキスト抽出時のみで、検索可能PDFの画像には原スクリーンショットを用います。

**注意:** 数式、図表、縦組、医学用語は誤認識されます。色つきの表や小さい脚注では特に崩れやすいため、NDLOCR-Liteの利用を勧めます。

## 保存されるファイル

```text
Documents/EbookTextStudio/書籍名/
 ├─ pages/page_00001.png ...       # 原キャプチャ（再処理に使う）
 ├─ manifest.json                  # 撮影条件と処理履歴
 ├─ native_text.json               # PDF由来なら元のテキスト
 ├─ replacements.json              # 任意の修正辞書（手編集）
 ├─ ocr_cache/                     # 認識結果とPDF作業用（再開可能）
 └─ output/
     ├─ 全文.md                     # AIで読むのに便利
     ├─ 全文.txt                    # プレーンテキスト
     ├─ 要確認.md                   # 数値・単位・範囲を含む行（原本と照合）
     ├─ OCR抜け確認.md              # OCRが読み落とした疑いのある箇所（赤枠画像は audit/）
     ├─ 画像PDF.pdf                 # 原画像から生成、画像のみ
     ├─ 検索可能PDF.pdf             # 原画像+OCR検索用テキスト層
     └─ pages/page_00001.txt ...   # ページ別テキスト
```

`replacements.json` は最初の実行時に `{}` として作成されます。必要なら `{"CKDl": "CKD1"}` のような辞書を**自分で追加**してください。誤った修正も生じうるため、医療用語の一括置換には慎重になってください。

## 途中から再実行する

- 撮影: 同じ書名のフォルダに追記されます。再開位置を**利用者がビューアで指定**してください。前の最後のページを再び写した場合は同一画像判定で重複防止を試みます。
- OCR: ページのハッシュと認識設定によるキャッシュが使われます。**エンジンやOCR設定を変えたときは再OCR**します。医学用語の置換辞書の編集だけならテキスト表示に反映され、OCR本体の再実行は不要です。
- OCR停止はページ単位（NDLOCRバッチの場合はプロセスを終了）。途中まで作成したキャッシュは残ります。作成途中のPDFは`.partial.pdf`として残る場合があり、完成PDFと区別します。

## iPadから使う

Windowsの保存先をiCloud Drive/OneDrive等に設定し、iPadから `output/全文.md` と `検索可能PDF.pdf` を読む構成が手軽です。クラウドAIに本を丸ごとアップロードする場合には著作権・電子書籍の契約条件・プライバシーに注意してください。

## CLIでの一括OCR（上級者向け）

画面撮影後の**画像フォルダやPDFが複数ある場合**は、コマンドで順番に処理できます。Kindleビューアから複数冊を自動選択する機能ではありません。

```powershell
# 画像フォルダ1冊を取り込み、OCRする
.venv\Scripts\python.exe cli.py one --input "C:\Books\my_pages" --base "C:\EbookText" --title "腎臓内科学"

# C:\Books\incoming の「サブフォルダ」または「PDF」を1冊ずつ処理
.venv\Scripts\python.exe cli.py batch --input "C:\Books\incoming" --base "C:\EbookText"
```

すでに変換済みの書籍は、キャッシュを使って再処理を最小限に抑えます。取り込み時の整形は `--no-strip-bars`（バー除去しない）、`--no-split`（見開きを分割しない）、`--rtl`（右開き）、後処理は `--no-clean`、低信頼行の再読みは `--no-reread`、並列数は `--workers N` で切り替えられます。`--engine NDLOCR-Lite --ndl-command ndlocr-lite` で別のOCRエンジンを指定することもできます。

### テストの実行

画面撮影とGUIはWindows専用ですが、OCR・取り込み・PDF生成のテストはLinux/macOSでも実行できます。OCRのテストにはTesseract本体と英語データ（`eng`）が必要です。

```bash
# Ubuntu/Debianの例
sudo apt-get install -y tesseract-ocr tesseract-ocr-jpn

python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q tests
```

テストフォント（DejaVu Sans）が `/usr/share/fonts/truetype/dejavu/` にない環境では、`tests/test_ocr.py` のフォントパスを調整してください。

### 技術上の制約

- Kindleを含む各ビューア固有の動作はWindows実機で未検証です。キーボード操作や画面保護により動作しない場合があります。
- 表は**罫線のある表**を復元します。罫線の無い（横線だけの）表、数式、写真の内容はまだ構造化できません（図として画像で残ります）。本文中の小さな番号札（「（表17）」など）はOCRの誤読がそのまま残ることがあります。
- PDFのテキストレイヤーは検索補助用で、特にNDLOCRの日本語/縦組では文字位置の厳密な保証がありません。
- 全処理はローカルで完結します。インストール時のpipや任意のNDLOCRセットアップだけがインターネットを使います。

### ソースコード

主な処理は`ebooktext/capture.py`、`ebooktext/ocr.py`、`ebooktext/importer.py`（取り込み）、`ebooktext/pageprep.py`（ステータスバー除去・見開き分割）、`ebooktext/linereread.py`（低信頼行の再読み）、`ebooktext/textclean.py`（後処理・要確認行）に分割しています。すべてPythonの通常のスクリプトで、利用者が自由に変更可能です。
